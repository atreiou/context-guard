# NEVER CONTRADICT THESE DECISIONS WITHOUT EXPLICIT USER APPROVAL
# These are the "why" behind every major choice. Summaries lose the "why"; this file preserves it.
#
# Every decision has a mandatory Category field. It must be one of:
#   - forever-active    : never archive (style rules, brand, philosophy, British English, "no abbreviations")
#   - active-constraint : archive only when the governed system is permanently retired
#   - feature-specific  : archive when the feature is built, tested, user-signed-off, no related work queued
#   - superseded        : archive immediately on supersession (keep the new one, archive the original)
#
# If uncertain, default to active-constraint (the safe choice, since it won't auto-archive).
#
# Entry format:
#
# ## D-001: [Title] (YYYY-MM-DD)
# **Category:** active-constraint
# **Decision:** [The choice that was made]
# **Rationale:** [The reasoning that led to it]
# **Source:** [User comment | Plan | Session | External requirement]
# **Affects:** T-001, T-045  (optional, tasks this governs)
#
# ROTATION: decisions older than the last 5 sessions move, full text intact, into
# archive/DECISIONS_page1.md, archive/DECISIONS_page2.md, etc. Each one leaves a one-line entry in the index
# below. ARCHIVING DOES NOT REVOKE A DECISION. Forever-active and active-constraint decisions
# govern from the archive exactly as they did from here. The index is how future sessions find
# them, and it is why this file can stay small without any rule going missing.
